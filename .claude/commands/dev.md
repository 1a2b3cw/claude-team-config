# /dev - 开发流程

根据任务复杂度自动选择流程。

## 流程

### Step 1：评估复杂度
根据用户需求判断任务级别：
- **S（热修）**：1-10 行修复 → 直接跳到 Step 3
- **M（小功能）**：单模块 → 跳到 Step 3
- **L（中功能）**：跨模块 → 执行完整流程
- **XL（大功能）**：新系统 → 执行完整流程 + Spike

### Step 2：规划（L/XL 级）
1. **Spike**（可选）：Researcher + Architect-Planner 并行调研可行性
2. **Plan**：Architect-Planner 输出 spec.md + tasks.md
3. 与用户确认计划

### Step 3：迭代开发
对 tasks.md 中的任务分批迭代：
1. 选择 1-3 个任务作为本次迭代
2. **Builder** TDD 实现
3. **持续审查**：Builder 完成后立即 Reviewer 审查（质量+安全+性能+无障碍）
4. 修复审查发现的问题
5. 标记任务完成，进入下一批迭代

### Step 4：验收
1. 运行所有测试
2. 集成验证
3. 确认任务全部完成

## 使用方式
```
/dev 做一个用户注册登录功能
/dev 修复登录页面样式问题
/dev 重构认证模块
```

## 与旧版的区别
- 不再是 5 个串行阶段
- Review 在迭代中持续进行，不等到最后
- Security Auditor 合并到 Reviewer，安全检查贯穿全程
- 小任务跳过规划，直接写代码
