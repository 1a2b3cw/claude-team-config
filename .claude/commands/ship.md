# /ship - 发布前检查

代码发布前的全面检查。

## 检查清单

### 1. 代码检查
- [ ] 所有测试通过
- [ ] 类型检查通过（tsc --noEmit）
- [ ] Lint 无错误
- [ ] 无 TODO/FIXME 遗留（或已记录）

### 2. 安全检查
- [ ] npm audit 无 high/critical 漏洞
- [ ] 无硬编码密钥
- [ ] 输入已验证（Zod schema）
- [ ] 权限已检查

### 3. 性能检查
- [ ] Core Web Vitals 达标（LCP < 2.5s, CLS < 0.1）
- [ ] 无 N+1 查询
- [ ] 大列表已分页
- [ ] 图片已优化

### 4. 无障碍检查
- [ ] 关键交互元素有 aria 标签
- [ ] 颜色对比度达标
- [ ] 键盘可操作

### 5. 配置检查
- [ ] 环境变量已配置（.env.example 完整）
- [ ] 数据库迁移已准备（含 rollback）
- [ ] CI/CD 配置已更新

### 6. Git 检查
- [ ] 分支命名规范
- [ ] commit message 清晰
- [ ] 无敏感文件

## 输出格式

```markdown
# 发布检查报告

## 结论：可以发布 / 需要修复后发布

✅ 通过 | ❌ 未通过 | ⚠️ 警告

| 检查项 | 结果 | 备注 |
|--------|------|------|
| 测试 | ✅ | |
| 类型 | ✅ | |
| 安全 | ⚠️ | 1 个中等漏洞 |
| 性能 | ✅ | |
| 无障碍 | ✅ | |

## 发布步骤
1. [具体步骤]
```

## 使用方式
```
/ship
```
