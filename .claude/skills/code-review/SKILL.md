# 代码审查（含安全审计）

## 触发条件
- PR 审查、代码合并前
- 用户要求审查代码
- M 及以上任务完成后

## 审查维度（一次完成）

### 1. 正确性
- 逻辑正确、边界条件、空值/undefined 处理
- 错误处理完善、并发/异步正确

### 2. 安全性（原 Security Auditor 职责）
- **注入**：SQL 参数化、XSS 转义、命令注入
- **认证**：JWT 最佳实践、密码哈希（bcrypt/argon2）
- **授权**：RBAC 权限检查、水平/垂直越权
- **密钥**：无硬编码、环境变量管理
- **输入验证**：Zod schema、allowlist > denylist
- **CSRF**：Cookie 认证场景需防护
- **安全头**：CSP、HSTS、X-Content-Type-Options
- **依赖**：npm audit 无 high/critical

### 3. 性能
- N+1 查询、不必要的重渲染、内存泄漏
- 大数据分页/流式处理、图片优化

### 4. 可维护性
- 命名清晰、单一职责、无重复代码
- 复杂度可控、注释必要且准确

### 5. 测试
- 核心逻辑有测试、测试有意义
- 边界条件测试、测试独立可重复

### 6. 无障碍
- 关键交互元素有 aria 标签
- 颜色对比度达标（WCAG AA）
- 键盘可操作

## 审查流程
1. 快速扫描：了解变更范围和目的
2. 逐文件审查：按维度逐项检查
3. 交叉验证：变更之间是否一致
4. 整体评估：架构和设计层面
5. 输出报告：按严重程度分类

## 输出格式

```markdown
# 审查报告

## 结论：通过 / 需要修改 / 需要重大修改

## 严重问题 🔴
1. **[文件:行号]** - [问题] → [修复建议]

## 中等问题 🟡
1. ...

## 轻微问题 🟢
1. ...

## 优点 👍
1. ...

## 评分
- 正确性：X/10 | 安全：X/10 | 性能：X/10 | 可维护：X/10 | 测试：X/10
```

## 审查原则
- 解释 WHY，不只说 WHAT
- 提供修复代码，不只指出问题
- 区分"必须改"和"建议改"
- 安全问题零容忍，标记为严重

## 安全检查清单（OWASP Top 10 速查）

| 类别 | 检查项 |
|------|--------|
| 访问控制 | 权限检查、水平/垂直越权、API 端点认证 |
| 加密 | 密码哈希、HTTPS、敏感数据加密、无硬编码密钥 |
| 注入 | SQL 参数化、XSS 转义、命令注入 |
| 安全配置 | 无默认密码、CORS 配置、错误信息不泄露 |
| 身份认证 | 密码策略、暴力破解防护、Token 安全 |
| SSRF | 用户 URL 验证、内网访问限制 |
